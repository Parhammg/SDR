    Lab 01 — RF Spectrum Monitoring

    Team 01 · SeyedParham Moghaddasi and Amirali Rajai

    • Report PDF and editable report
    • Lab manual and reconstructed logbook
    • Offline results with full filenames, sample counts, bandwidth edges, timing detections and GSM frequency estimates

    Reproduce the offline results

    From this directory, with Python 3 and the eight .cf32 files present:

    python -m pip install numpy scipy matplotlib
python analyze_lab01.py

    The script writes the three generated PNGs and lab01_results.json under images/. --data and --output accept alternative directories. The captures are little-endian interleaved float32 I/Q with no header. Existing names use Team_01; newly recorded files use Team-01. The archived filenames encode tuned RX LO in hertz, sample rate in samples per second, requested gain in dB, and capture timestamp. log.md maps every archived file to its role.

    Regenerate the PDF from the editable source with python -m pip install markdown and python build_lab01_report.py. The renderer uses Chrome, Edge, or Chromium. Supply --browser PATH if your browser is installed elsewhere.

    Run and check the GNU Radio flowgraphs

    Use GNU Radio 3.10 with Qt and gr-iio, such as the activated radioconda environment on Windows. Open lab01_monitor.grc for receive-only operation or lab01_loopback.grc for cabled loopback, then generate and run from GRC. The corresponding .py files are also runnable in the same environment.

    grcc -o . lab01_monitor.grc lab01_loopback.grc
python -B check_recorder.py

    The test uses a GNU Radio +100 kHz complex source, a Throttle and a finite stream. It also checks the exact sample cap, arming, capture-setting changes, file format and close on flowgraph stop. sdrlab_iq_recorder.py is the source for both GRC Embedded Python Blocks. After editing it, paste the complete source into each block and regenerate. Close the Qt window to stop cleanly. Use a fresh arm after a rate, LO or gain change. Recordings go in recordings/ under the working directory, capped at 80 MB or 4 s. A second capture with identical settings and the same timestamp uses the next unused timestamp to avoid overwriting evidence.

    Setup and device readback

    Use LAN for IIO data and USB for power. Use RX1 for the antenna in monitor mode and leave TX1 empty. Stop the flowgraph before changing cabling. For the lab's cable-only loopback, follow the bench's approved attenuation setup, start at 60 dB TX attenuation, keep attenuation at or above 40 dB and manual RX gain at or below 10 dB. For the mobile uplink demonstration, keep the phone at least 5 m away and start at 0 dB RX gain. Run only one streaming app at a time.

    ping 192.168.1.10
iio_attr -u ip:192.168.1.10 -C
iio_attr -u ip:192.168.1.10 -c ad9361-phy altvoltage0 frequency_available
iio_attr -u ip:192.168.1.10 -c ad9361-phy altvoltage0 frequency
iio_attr -u ip:192.168.1.10 -i -c ad9361-phy voltage0 sampling_frequency
iio_attr -u ip:192.168.1.10 -i -c ad9361-phy voltage0 rf_bandwidth
iio_attr -u ip:192.168.1.10 -i -c ad9361-phy voltage0 gain_control_mode
iio_attr -u ip:192.168.1.10 -i -c ad9361-phy voltage0 hardwaregain

    Save console output during the acquisition. The installed GNU Radio 3.10.12 Pluto source generates set_filter_params('Off', …) but omits an RX bandwidth setter. The 20 MHz GRC field therefore needs a device readback. For 20 MS/s surveys, use a 1024-point FFT, Average = None, and clear Max Hold between steps. Use 2.6 MS/s for recording burst timing. The report identifies the specific hardware evidence that still needs to be captured.
